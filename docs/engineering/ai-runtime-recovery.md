# AI 原请求跨页面恢复

日期：2026-11-03。对应 APP-09 / API-AI-02。沿用 OpenAPI 1.51.1 / 143 操作、原 UUID 幂等协议与显式重试，没有新增接口、依赖或迁移。

原会话控制器只在自身保存 pending 请求。完全卸载后，即使后端已保存回答，重进页面也无法取回原 clientRequestId。本轮增加 `AiTurnRecovery`，按 QueryClient 对象、账号 ID 和规范化会话 UUID 隔离，在当前运行期保存原请求 DTO。新页面先完成已授权历史读取，再展示待确认问题并允许使用原键重试；普通发送被待确认请求阻止，不自动调用模型。

账本只保存内存中的请求 UUID、原问题文本和当前操作所有权，不持久保存凭证、流式片段或回答。新控制器使用新的 session epoch 和身份端口，不能沿用旧登录凭证。不同账号、会话和 QueryClient 互相隔离。同账号在同一 QueryClient 中重新登录可继续恢复，进程退出、完整页面刷新或换设备后不保留；本轮不声称持久恢复已完成。

同一运行期同一会话的活动操作在身份请求前同步取得所有权，其他实例不能另发问题、重试或编辑。失焦、卸载和停止接收会终止本地控制器并释放接收所有权，保留原 DTO；用户此后可显式使用同一个 UUID 重试。原服务端幂等流程负责识别处理中或已保存请求。旧流的片段、完成、错误或 finally 不得清除新实例的请求、确认结果和所有权。取消接收不能撤销远端工作，也不保证立即停止模型计费。

原“编辑后新建”行为保留：这是用户主动放弃原键，编辑后的发送会生成新键，可能产生新的回答。它不能在活动接收或权限拒绝时执行；401/403/404 后仍隐藏本地回答并禁止重试/编辑，直到重新取得已授权历史。其他实例完成或放弃待确认请求后，会同步移除旧提示；回答内容仍以服务端历史和已确认消息 ID 为准。

新增 15 项跨实例恢复测试，AI 专项合计 191 项通过。覆盖完整重建、原 DTO、同步门禁、停止/卸载后的迟到结果、权限拒绝、主动编辑、账号/会话/运行期隔离、过期所有权和输入复制。首轮旧回归三项失败，发现通用恢复提示覆盖了已授权历史读取后的清除动作；修正初始化提示的设置位置后，原断言保持并通过。

独立 HTTP/SSE 套件由三项扩为四项：原完成事件丢失用例增加完全卸载、切换另一账号的404隔离及同账号重新登录后的原键恢复；新增服务端已经提交但旧响应仍延迟时，由新控制器使用原键取回同一结果。后置 PostgreSQL/pgvector 断言要求两会话共三轮、六条持久消息、一次软删除，只有三次模型和三次问题 Embedding 调用，所有提示词/引用仅含公开来源。模型与 Embedding 是本机 HTTP 替身，SecureStore 为内存替身；实际 API、SSE、认证、查询和持久层均按独立套件范围运行。

完整运行结果、源码与日志摘要见[本仓验证报告](../validation/ai-runtime-recovery-20261103.json)。独立后端准备步骤见[原生 AI HTTP 说明](../../../backend/docs/engineering/ai-runtime-recovery-http.md)。本仓只使用 HTTP，不导入后端代码或直连数据库。

本仓复现：独立执行 `pnpm install --frozen-lockfile`、`pnpm check`；AI 专项为 `pnpm exec vitest run src/features/ai/`。后端提供独立回环服务后，设置 `EXPO_PUBLIC_API_BASE_URL`、非凭证 `AI_MOBILE_FIXTURE_JSON` 和进程内随机 `AI_MOBILE_FIXTURE_PASSWORD`，执行 `pnpm test:ai-http`。测试仅接受专用库标记。

修改前核对 expo ~58.0.22、expo-router ~58.0.29，并读取 [SDK 58](https://docs.expo.dev/versions/v58.0.0/) 和 [Router hooks](https://docs.expo.dev/router/reference/hooks/)。保持现有 useFocusEffect 清理与归档只读规则，没有新 Expo API 或原生模块。控制器替换不是实际 React 导航/设备验收；真实模型供应商、设备、安全存储及生产恢复仍待完成。
