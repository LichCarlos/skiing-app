# 社区阅读、账号隔离与操作核对

日期：2026-10-31。对应 APP-01/02、API-C01/C03/C04，继续消费 OpenAPI 1.41.0。Expo ~58.0.21、React Native 0.88.1；查阅 SDK 58 与 TextInput/Alert 文档后沿用现有组件，不新增依赖或原生模块。删除确认采用页面内确认/取消，可在三个导出平台使用。

## 阅读与缓存

信息流等待会话恢复，按账号与有效关键词隔离缓存；登录用户的列表/详情读取先核对 /auth/me，游客 likedByMe 强制 false。查询入口校验关键词 200 字符、limit 1–100、游标长度/字符集、详情正 int4 和评论偏移边界；游标内部语义仍由服务端解释，客户端不解析其 JSON 或生成业务游标。所有公开读取在请求前后复核取消，身份核对后的取消不会继续发起个人化请求。

信息流加载更多/刷新失败时保留已有卡片，显示对应重试入口；加载更多失败暂停自动触底重试。详情 ID 无效时直接给出提示，避免停在永久 loading。评论只在公开详情成功后读取，仍采用独立偏移分页。

## 写入与账号生命周期

每个详情组件按账号、会话状态和动态 ID 创建独立 CommunityActionGate。同步锁覆盖身份读取、一次写入及结果处理，避免重复点击在 React 重绘前产生重复评论，也不允许同屏点赞/删除/评论相互重叠。每次操作核对当前账号；离开或账号变化时取消信号，忽略旧响应及旧组件后续回调。点赞只更新当前账号的信息流缓存前缀，不把个人状态写入其他账号或游客缓存。

动态与评论删除先在页面确认。普通 4xx 拒绝可以修正后重试；网络、408 或 5xx 可能发生在写入已提交之后，界面显示结果未确认，暂停继续写入，先刷新详情/评论，再由用户点击“已核对，继续操作”。客户端不会自动重发评论；若服务端已明确成功而缓存刷新失败，提示操作已完成但刷新失败。

这些措施没有为评论 POST 新增服务端幂等键，不能保证跨页面、跨设备或重新启动后的去重，也不等同于所有在途登录/撤权竞争已被消除；后端始终按实际请求主体及 owner/grants 校验。

## 验证范围

新增 35 项测试：15 项操作门禁测试覆盖同步重复点击、身份变化、取消/迟到结果、生命周期重建、4xx 与不确定结果分类、显式核对、已提交结果后刷新失败；20 项公开读取测试覆盖输入边界、缓存账号分区、游客/本人状态及取消。与原发布/本人动态 transport 测试一起，社区模块 60 项通过。没有把纯逻辑/transport 测试称作 React Native 组件或真实设备测试。
