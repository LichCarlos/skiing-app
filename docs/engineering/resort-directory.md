# Expo 雪场组合筛选

日期：2026-10-31。对应 APP-04、API-R01；Expo ~58.0.21、React Native 0.88.1。查阅 [Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/)、[Expo 文档索引](https://docs.expo.dev/llms.txt) 与 [TextInput](https://reactnative.dev/docs/textinput)。不新增原生模块或依赖。

## 页面与工程边界

雪场页使用本仓 OpenAPI 1.41.0 生成的 PublicResortCardVO/PageVO 与 query 联合类型，替换原手写响应结构。`src/features/resorts/resort-query.ts` 负责组合参数、边界、读取与缓存键；`resort-filters.tsx` 为独立移动表单；路由页保留 InfiniteQuery、收藏和详情导航。Web/Backend 只共享协议和约束，不引用它们的实现代码。

搜索框支持名称/地区关键词；展开筛选可填写省/市/区县、最低/最高整数票价、最低评分、营业状态、参考坐标，以及名称/价格/评分/距离排序和方向。使用草稿与已应用条件两份交互状态；提交校验通过才更新查询，错误保留输入。应用或清除筛选会重置对应账号/条件的 InfiniteQuery，从第一页开始；刷新/加载更多沿用全部已应用条件。

坐标可为零且须成对，纬度 -90–90、经度 -180–180；距离排序要求坐标。评分 0–5、价格非负且上下界有序，安全整数/分页偏移提前检查。列表展示服务端总数、完整地区、准确营业状态及直线距离；没有距离时省略，0 米正常展示。页面不申请设备定位权限。

公开标签选项目录尚待协议确认，因此完整标签多选 UI 尚未交付。查询模块已保留重复 fitTags 的独立编码及全部标签匹配协议，等待目录确认后接入选项，不内置业务标签或读取管理字典。

## 服务端状态与会话

InfiniteQuery key 包含 userId 与完整已应用查询，地区/金额/评分/状态/坐标/排序/标签变化均改变缓存分区；账号变化重建页面。会话恢复时暂停列表。登录后每次个人化读取先核对 `/auth/me` 的账号，游客强制 `favoriteByMe=false`，不会把传输层意外返回的收藏态当作游客状态。所有读取前后检查 AbortSignal，避免关闭页面后的迟到结果进入缓存。

客户端表单只提供输入校验；公开性、全部标签筛选、稳定排序、分页和收藏关系由后端负责。前端不提交 userId/merchantId、不直连数据库。收藏写入和详情页仍沿用原流程，本阶段没有把该流程描述为已完成全场景并发验收。
