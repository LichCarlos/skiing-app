# AI 会话列表工作流

2026-10-31，APP-08 基于 OpenAPI 1.44.0。页面 `/ai` 只组合查询、焦点与导航；`src/features/ai/conversation-list-run.ts` 管理一个账号页面实例的读写生命周期，`conversation-list.tsx` 展示列表和操作状态。未增加业务接口、迁移或依赖。

## 已实现的交互

- 每页 20 条，查询键含账号和页码。每次列表读取以及新建/删除前，都通过无缓存 `/auth/me` 核实当前账号与 `ai:conversation:use`；服务端继续负责授权和所有权。焦点恢复后先重新读取，未完成身份/列表复核前不展示缓存记录。读取错误时隐藏旧列表；写前身份失败同样隐藏旧记录。
- 新建发送 `{}`，不接收 title 或 owner；新建与软删除共用同步提交锁，在身份请求之前加锁，防止快速点击及两种操作交叉提交。写入期间禁用分页、删除确认、刷新和详情导航。
- 创建成功立即跳转到服务端返回的 UUID 会话地址。列表失效处理独立捕获失败，不再让列表刷新阻止已确认的创建跳转。删除确认后关闭确认框、清除该会话详情缓存并刷新列表；不伪造本地删除总数。
- 刷新返回权威 total 后，页码超过最后一页就回到有效末页并重新查询；全部删除时保留第 1 页空状态。切页清理删除确认，返回焦点也清理旧确认。
- `useFocusEffect(useCallback(...))` 清理失焦和卸载请求。列表请求同时响应查询取消与焦点取消；写入取消传递到网络。旧生命周期的响应、错误和 finally 不得触发跳转、清理新写锁或更新账号页面。

## 写入结果不确定时

写入调用开始后的网络错误、408、5xx、畸形创建结果，以及结果返回前的失焦取消，均可能已经在服务端完成。页面保留“先刷新核对”提示并暂停新写入，不自动重发。明确的其他 4xx 按拒绝处理。

用户可刷新和翻页核对。只有在不确定结果出现之后发起并成功完成的身份/列表读取，才允许点击“已核对列表，继续操作”；该按钮表示用户明确继续，列表暂未出现记录不能证明原写入失败。新建接口没有幂等键，本阶段没有提供服务端新建去重；发送消息的 UUID 幂等协议不用于创建会话。

此恢复标记只属于当前账号的已挂载页面实例，支持失焦后返回；完整卸载、App 重启及跨设备不保存。取消 HTTP 接收不能撤销服务端已执行的写入。身份预检也不承诺消除预检之后全部在途撤权或凭证切换竞争，后端仍负责最终授权。
