# AI 会话列表跨页面核对恢复

2026-11-03，APP-08 / API-AI-01。沿用 OpenAPI 1.51.1 / 143 操作及24项迁移，没有新增接口、创建幂等协议、依赖或数据库字段。

原页面已经在创建、删除结果不明时禁止重复操作，并提供刷新列表和人工核对。但状态只在单个控制器内，完全卸载或同账号重新登录后丢失。本轮增加 `AiListRecovery`，按 QueryClient 对象和账号 ID 隔离，保存内存中的待核对标记、操作类型、任务所有权与修订号。页面重建使用新的 session epoch 和身份端口；另一账号不继承标记，原账号在同一运行期重登仍保留。账本不保存凭证、会话标题、提问内容或列表结果。

创建和删除在身份校验前同步取得同账号的共享所有权，其他实例不能同时写入。身份预检阶段卸载后，旧实例已不能发送，可立即释放；已经发出的请求即使本地取消，也要等原 Promise 结束才释放。失焦、卸载后不再调用旧导航、缓存和页面回调；迟到成功不算新页面已确认成功。完成与取消均通过所有权校验，旧 finally 不释放新任务。

待核对标记保留到用户完成现有人工流程：原异步任务结束后，新页面成功读取并通过前后身份校验，再显式点击“已核对列表，继续操作”。读取跨越另一次操作或任务结束的修订号，不能解除保护；读取失败、权限拒绝、仍在读取或仍有任务均不允许确认。其他实例的操作会使旧核对失效，标记清除也同步移除其他页面提示。界面在旧任务未结束时显示等待说明。

创建接口没有幂等键或专用结果查询，本轮不自动重放创建、删除，也不声称列表核对能证明远端请求已终止。客户端 Promise 结束可能早于远端工作完成；用户主动继续仍可能造成重复会话，既有风险说明保留。内存标记不跨进程退出、完整刷新或设备；持久恢复需要另行明确产品协议。

新增22项回归：20项恢复/隔离/所有权及读取竞态测试和2项等待界面测试。AI专项213项通过，并修订一项旧测试，要求卸载后的原任务结束后重新读取才能继续，不再允许原异步请求未结束时直接解除保护。并发读取只允许最新代次更新状态，旧成功不能覆盖新拒绝，旧失败不能清除新核对。

独立 HTTP/SSE 套件保持4项，增强其中两项：创建响应在真实API提交后被丢弃，完全卸载、切换账号、同账号重登后通过列表找到唯一会话，没有第二次创建；删除已提交但响应延迟时，卸载及重登后仍禁止创建和删除，释放旧响应后还须重新读取、人工确认。另保留原消息UUID重放、迟到旧流和公开引用验证。后端核对两会话、三轮六消息、一次软删除，以及三次模型/Embedding调用。模型与Embedding为本机HTTP替身，SecureStore为内存替身；实际服务端HTTP/SSE、认证与PostgreSQL/pgvector不替换。最终结果以[本仓验证报告](../validation/ai-list-recovery-20261103.json)为准。

修改前核对 expo ~58.0.22、expo-router ~58.0.29，查阅[SDK58](https://docs.expo.dev/versions/v58.0.0/)和[Router hooks](https://docs.expo.dev/router/reference/hooks/)。继续使用现有 useFocusEffect 清理，无新原生API或模块。专项复现为 `pnpm exec vitest run src/features/ai/`；独立安装与完整验证执行 `pnpm install --frozen-lockfile`、`pnpm check`。后端提供一次性本地服务后，按现有[AI HTTP说明](../../../backend/docs/engineering/ai-runtime-recovery-http.md)运行 `pnpm test:ai-http`。
